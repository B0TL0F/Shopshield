# Docker: learn locally first

Use WSL2 Ubuntu with Docker Desktop's WSL integration and Linux containers on Windows. All shell commands in these guides use Bash. Install Git, Python 3.12+, Azure CLI, Terraform 1.9+, Helm 3 and kubectl. Verify each with `--version`. Never paste Bash syntax directly into PowerShell.

## `Dockerfile`

Each service builds into a separate image using `SERVICE`. The syntax check stage keeps its generated bytecode out of the runtime image. There are no third-party Python dependencies to install. Patch tags below are examples pinned for this guide; scan and update them as upstream security patches arrive. For stronger reproducibility replace tags with verified digests from your registry.

```dockerfile file=Dockerfile
FROM python:3.12.16-slim-bookworm AS check
ARG SERVICE
WORKDIR /build
COPY common.py .
COPY services/${SERVICE}.py service.py
RUN python -m py_compile common.py service.py

FROM python:3.12.16-slim-bookworm AS runtime
ARG SERVICE
ENV PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1 CONTAINER=1 SERVICE=${SERVICE}
WORKDIR /app
COPY --from=check --chown=10001:10001 /build/common.py /build/service.py ./
USER 10001:10001
EXPOSE 8080
CMD ["python", "common.py"]
```

## `compose.yaml`

YAML anchors reuse hardening. Only the gateway publishes a loopback port. Dependencies start asynchronously; retry requests after all containers have started. Application state is intentionally ephemeral.

```yaml file=compose.yaml
x-runtime: &runtime
  read_only: true
  user: "10001:10001"
  cap_drop: [ALL]
  security_opt: [no-new-privileges:true]
  tmpfs: [/tmp]
  mem_limit: 128m
  cpus: 0.5
  restart: unless-stopped
services:
  gateway:
    <<: *runtime
    build: {context: ., args: {SERVICE: gateway}}
    ports: ["127.0.0.1:8080:8080"]
  catalog:
    <<: *runtime
    build: {context: ., args: {SERVICE: catalog}}
  cart:
    <<: *runtime
    build: {context: ., args: {SERVICE: cart}}
  pricing:
    <<: *runtime
    build: {context: ., args: {SERVICE: pricing}}
  inventory:
    <<: *runtime
    build: {context: ., args: {SERVICE: inventory}}
  orders:
    <<: *runtime
    build: {context: ., args: {SERVICE: orders}}
  payments:
    <<: *runtime
    build: {context: ., args: {SERVICE: payments}}
  shipping:
    <<: *runtime
    build: {context: ., args: {SERVICE: shipping}}
  notifications:
    <<: *runtime
    build: {context: ., args: {SERVICE: notifications}}
  recommendations:
    <<: *runtime
    build: {context: ., args: {SERVICE: recommendations}}
```

## Run and inspect

```bash
python3 tests/integration.py
docker compose config --quiet
docker compose up --build -d
docker compose ps
curl --fail http://localhost:8080/products
curl --fail http://localhost:8080/recommendations
curl --fail -H 'Content-Type: application/json' http://localhost:8080/cart \
  -d '{"cart_id":"demo","items":[{"sku":"book","qty":2}]}'
curl --fail -H 'Content-Type: application/json' -H 'Idempotency-Key: checkout1' \
  http://localhost:8080/checkout \
  -d '{"cart_id":"demo","country":"IN","token":"demo-approved"}'
curl --fail http://localhost:8080/metrics
docker compose logs --tail=20 orders
docker compose down
```

Expected total: 3500 cents (two books plus shipping). Repeat checkout with the same key: the order ID should stay the same. Stop pricing, use a NEW key, and observe 503; restart pricing. Explain why process health remains green during that downstream outage.
